自运营 · 不依赖第三方网盘

自己的网盘，
自己的存储与规则。

文件存在你自己的对象存储（Cloudflare R2 / S3 / WebDAV），账号走 R6T5 Hub 通行证。支持分享链接、回收站、目录树与秒传去重，也能用 Docker 一键自托管。

用 Hub 账号登录 → 自托管部署

能做什么

面向个人与小团队的文件管理，存储层可替换，不锁定服务商。

🗂

目录树与拖拽上传

多级文件夹、批量上传、断点重传，大文件分片走对象存储直传，不经过 Worker 中转。

🔗

分享与权限

链接分享可设置密码、有效期、下载次数；目录分享只读、可追溯访问记录。

⚡

秒传与去重

按内容哈希去重，同一文件重复上传直接命中已有对象，省流量也省空间。

♻️

回收站

删除先进回收站，保留 30 天，可恢复或彻底清除；管理端可见容量占用。

🔐

Hub 通行证登录

与 r6t5 生态共用账号，一处登录，网盘、文档站、钱包通行。

🧩

开放 API

提供上传、列表、分享、回收站接口，方便接进自己的文档站或自动化流程。

三种形态

从「注册就能用」到「完全自己管」，同一套代码。

托管版

用 R6T5 提供的域名与存储，注册即用，配额按账号发放。

Docker 自托管

docker run 起一个实例，存储接自己的 R2 / S3 / 本地磁盘，数据不出自己的机器。

嵌入式

把文件选择器与上传组件嵌进自己的站点，鉴权仍走 Hub。

和公共网盘的区别

不评判别的产品，只说清自己的取舍。

维度R6T5 Drive公共网盘
存储位置自己的对象存储 / 磁盘服务商机房
账号体系R6T5 Hub 通行证各自独立账号
限速与配额由自己配置按会员等级
数据导出对象存储直读，随时迁走受客户端限制
可自托管支持 Docker不支持

路线图

先把「能用」做出来，再谈客户端与高级能力。

P0
项目骨架与介绍页

仓库、站点、架构说明；确定存储与鉴权方案。

P1
最小可用：上传 / 列表 / 下载 / 删除

Worker + R2，Hub 登录换 JWT，单用户空间。

P2
目录树、分享链接、回收站、秒传

元数据表与直传签名；分享密码与有效期。

P3
Docker 自托管与多存储后端

S3 / WebDAV / 本地磁盘适配，配置化部署。

P4
配额、团队空间、开放 API

按账号计容量，团队共享目录，对外提供 API。
